## Why This Framework Exists

Search has changed materially in the period between 2022 and 2026. The introduction of generative AI into search results — first through AI Overviews on Google, then through conversational interfaces, and now through AI-native search products — has altered what it means to be visible online.

At the same time, the fundamentals of technical SEO have grown more complex. Rendering environments, JavaScript frameworks, server-side rendering, edge delivery networks, and Core Web Vitals have added layers of infrastructure that directly affect how search engines discover, understand, and rank content.

The consequence is that auditing a web property for search performance now requires a broader competency than at any previous point in the discipline's history. An auditor must simultaneously evaluate:

- Infrastructure and crawl mechanics
- Content quality and information gain
- Entity associations and knowledge graph presence
- Link authority and digital trust signals
- AI readability and structured synthesis potential
- User experience and page experience signals
- Conversion architecture
- Measurement fidelity
- Competitive positioning

No single existing framework — from any toolset, agency, or standard — addresses all of these dimensions in a unified, evidence-based way. This gap is what the Growth AI SEO Audit Framework™ was designed to close.

---

## What This Framework Is

The Growth AI SEO Audit Framework™ is a proprietary methodology for conducting structured, reproducible SEO audits across enterprise and mid-market web properties.

It is organized around nine intelligence pillars, each representing a distinct domain of search and conversion performance. Each pillar contains a set of checkpoints. Each checkpoint is a discrete, independently auditable unit with a defined objective, procedure, evidence requirement, and pass/fail criteria.

The framework produces two types of output:

1. **The Growth AI Score™** — A composite metric from 0 to 100 that represents the overall health of a web property across all nine pillars.
2. **A structured audit report** — A document that captures findings, evidence, priority ratings, and recommended actions for each evaluated checkpoint.

---

## What This Framework Is Not

This framework is not a set of generic best practices. Every checkpoint is grounded in specific, verifiable behaviors that are known to affect search crawling, indexing, ranking, or conversion. Checkpoints that cannot be directly connected to a measurable outcome are excluded.

This framework is not a tool-specific workflow. While recommended tools are listed for each checkpoint, the procedures are designed to be tool-agnostic. Different practitioners may use different instruments to reach the same evaluation.

This framework is not static. Search evolves. Google's documentation evolves. AI search products evolve. This framework is designed for annual revision, with each edition reflecting the current state of search rather than the state at publication.

---

## Scope of Application

This framework applies to any web property where organic search traffic is a meaningful acquisition channel or a measurable business objective. It is applicable to:

- Corporate websites
- E-commerce sites
- SaaS product sites
- Content publishers and media properties
- Local business websites
- Professional services and B2B sites
- Multi-language and international sites

The framework is designed to scale. A full enterprise audit will evaluate all nine pillars with complete checkpoint coverage. A rapid audit for a smaller property may evaluate a subset of high-priority checkpoints within the most critical pillars. The scoring system accommodates both approaches transparently.

For practitioners new to this framework, begin with `PHILOSOPHY.md` to understand the governing principles, then read `METHODOLOGY.md` to understand the audit workflow, then read `SCORING.md` to understand how findings are weighted and scored.

After that, read each chapter in order. Each chapter introduces one intelligence pillar and provides the diagnostic lens for that domain.

For practitioners conducting an active audit, navigate directly to the relevant checkpoint files in the `/checkpoints/` directory. Each checkpoint is self-contained.

### Client and Stakeholder Reading

For clients and business stakeholders who need to understand what was evaluated and why, the executive summary template and the scoring overview in `SCORING.md` are the appropriate entry points.

## A Note on Language

This framework uses precise language. Terms are defined in the Glossary (`/appendix/glossary.md`) and used consistently throughout. Where a term has a common usage that differs from its usage in this framework, the distinction is noted.

The framework does not use hedging language. Findings are stated as findings. Criteria are stated as criteria. Where uncertainty exists — for example, where Google's behavior is undocumented or where empirical evidence is limited — that uncertainty is stated explicitly.
